# AI-BRAIN web dashboard (Build Phase 33-34)

A thin Next.js client over the `api/` FastAPI backend (Build Phase 33,
Part 1). Contains no business logic of its own -- every real decision
(what agents exist, whether a component is configured, what a Kernel
run actually did) comes from that backend.

Stack: Next.js (App Router) + TypeScript + Tailwind CSS + hand-written
shadcn/ui-style primitives (`components/ui/`) + `@xyflow/react` (MIT)
for the workflow canvas + `framer-motion` (MIT, Build Phase 34) for a
few micro-interactions. Dark-mode-first, styled after the
Vercel/Linear/Cal.com family of dashboards.

**Confirmed working on a real machine as of Build Phase 33**: dashboard,
system status, registered agents, task runner, and the workflow canvas
all render and fetch correctly against a real `uvicorn` backend. Build
Phase 34 (visual overhaul + a real audit-log page) has NOT yet had its
own real-machine confirmation -- see "First-time setup" below.

## First-time setup

Confirmed real-machine gotchas from the first setup round, in case you
hit them again on a fresh machine:

- **Node.js not installed / not on PATH**: install it (e.g.
  `winget install OpenJS.NodeJS.LTS`), then open a **brand-new**
  PowerShell window -- `node`/`npm` will not appear in a window that
  was already open. If a new window still doesn't see it, run
  `$env:Path += ";C:\Program Files\nodejs\"` once per window as a
  workaround, or restart the machine once for a permanent fix.
- **"fetch failed" on the dashboard even though `npm run dev` is
  running**: almost always means the `api/` backend (`uvicorn`) simply
  isn't running (or was stopped, e.g. to run `pytest`, and never
  restarted) -- start it again in its own separate terminal window and
  leave it running.
- **`npm run dev` picks port 3001 instead of 3000**: means an older
  `npm run dev` process from an earlier terminal window is still
  holding port 3000 -- either use the printed port, or close that old
  window.

```powershell
cd web
npm install
copy .env.local.example .env.local
npm run dev
```

Then, in a separate terminal (keep it running), the real backend:

```powershell
pip install fastapi uvicorn
uvicorn api.app:create_app --factory --port 8000
```

Open http://localhost:3000 -- you should see a sidebar (Dashboard /
Workflow canvas / Audit log), the system-status grid, the three
registered agents, a box to submit a real task to the Kernel, the
workflow canvas showing them as connected nodes, and a real audit-log
view.

**If you already ran `npm install` before Build Phase 34**: run it
again -- `framer-motion` was added as a new dependency.

## Optional: pull in more real shadcn/ui components

`components/ui/button.tsx`, `card.tsx`, `badge.tsx`, and `skeleton.tsx`
were hand-written to match shadcn/ui's own real, current source
structure exactly (same `cva` variant shape, same `cn()` helper, same
CSS variable names in `tailwind.config.ts`/`globals.css`) rather than
generated by shadcn's own CLI, because that CLI itself needs to
download from npm at run time -- also blocked in the sandbox this was
written in. Your machine can run the real thing directly, and it will
merge cleanly into this same convention:

```powershell
npx shadcn@latest init
npx shadcn@latest add input dialog select tabs
```

## What's new in Build Phase 34

- A persistent sidebar app shell (`components/app-shell.tsx`) replacing
  the old per-page "back to dashboard" link -- Dashboard, Workflow
  canvas, and a new **Audit log** page.
- A real audit-log page (`app/audit-log/page.tsx` +
  `components/audit-log-table.tsx`) -- the first UI for
  `GET /audit-log/recent` (an endpoint that existed since Build Phase
  33 Part 1 but had no consumer until now). Each row expands to the
  full raw event JSON.
- Route-level loading skeletons (`app/loading.tsx`,
  `app/workflows/loading.tsx`, `app/audit-log/loading.tsx`,
  `components/ui/skeleton.tsx`) so a slow/unreachable backend shows a
  recognizable loading shape instead of a blank flash.
- Icons throughout (`lib/icons.ts` maps agent/component names to a
  `lucide-react` icon), a custom workflow-canvas node design (icon +
  gradient + hover glow instead of a plain box), a subtle dot-grid
  background, a slim custom scrollbar, and small `framer-motion`
  micro-interactions (the active sidebar link, staggered card
  fade-ins).

## What's deliberately not built yet

- The workflow canvas (`components/workflow-canvas.tsx`) shows a
  STATIC view of the three agents in their documented pipeline order
  -- it does not yet read a real `WorkflowDefinition`/`WorkflowStep`
  configuration, is not yet editable, and does not yet show live
  per-node execution status while a `Kernel.run()` call is in
  progress (that needs a WebSocket endpoint on the backend, not yet
  built).
- No authentication/login screen yet -- this is a local dashboard
  talking to a local backend.
- No light-mode toggle -- dark-mode-only for now.
